# 2026-11-28: B26, "Made it home" is said once

- Before: the "Made it home" button was only off while one send was running.
  Every further tap wrote another row, and every phone in the lobby showed
  "... is safely at the fortress of dreams." again.
- Now: once the current user has sent it in this lobby, the button's place
  shows a plain green line, "You made it home" with a tick. It appears at
  once after a successful send, and again when the lobby screen is opened
  later, on this or another phone of the same user.
- How the screen knows: the lobby load returns all rows of the lobby, the
  "made it home" rows included, and each row carries the user id of who
  wrote it. `MadeItHomeOnce.hasSent` looks for such a row by the current
  user. It goes by the user id, not by the nickname in the row, so a friend
  with the same nickname, or an earlier nickname of one's own, does not
  confuse it.
- `LobbyView`: a flag `hasSentMadeItHome`, set from the rows at each full
  load and directly after a successful send; the button or the line
  depending on it; `sendMadeItHome` returns early when it was sent already
  or a send is running.
- Decisions made, say so if they should differ:
  - The line is also shown after the lobby has closed (in place of the
    greyed button).
  - There is no way to take a "Made it home" back or to send it a second
    time in the same lobby (for example after going out again).
  - What S10 does is untouched: the first send still ends location sharing
    for this visit, with the same status line.
  - The service does not refuse a second send. It would need a request of
    its own to find out, and the screen no longer offers the button. A
    modified client can still write several rows; the database rule belongs
    with B5 (`lobby_events`).
  - The 30-second refresh does not set the flag. It only matters when the
    same user sends it from a second phone while this one has the lobby
    open; this phone shows the line after the next pull-to-refresh.
- Tests: `MadeItHomeOnceTests`.
- Verified: build and unit tests in CI. This workspace cannot run the app.
- Human check on a device (two phones in one lobby):
  - Tap "Made it home": the status line appears as before, the button turns
    into "You made it home", and the other phone shows the message once.
  - Leave the lobby screen and open the lobby again: the line is still
    there, no button.
  - The other phone still has its own "Made it home" button.
  - If location sharing was on: the pin is gone as before (S10).
